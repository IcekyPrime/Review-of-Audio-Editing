### 笔记

#### MingTok-Audio？

>   VAE?

    VAE，连续潜在表示，生成质量优于离散token

MingTok-Audio 在功能上设计更为复杂（较于Audio-Omni和UNISON的VAE）。它的训练将与 LLM 的训练相结合，使得其对于作为文本分词处理和音频编辑\生成主干的 LLM 的语义空间更敏感。

架构是 编码器-语义模块-解码器。

这个模块的训练有三个阶段：

- 声学重建训练：

    学习一个高质量的基础声学编解码器，确保从波形到潜变量再回波形的重建保真度。

    只训练编码器 + 解码器。语义模块在此阶段不参与训练（或尚未引入）。

    采用 VAE-GAN 的目标函数进行训练。

    >   VAE-GAN?

- 语义特征蒸馏：

    只训练语义模块（移植了Whisper large-v3编码器）。

    >   Whisper large-v3?
        
        原始的 Whisper large-v3 编码器接收梅尔谱图（Mel-spectrogram） 作为输入，输出高维语义特征。

    原始的 Whisper large-v3 作为教师模型，复用的（移除卷积层的）Whisper large-v3 作为学生模型（蒸馏）。

- 统一分词器与 LLM 联合训练：

    使用最终用于生成、理解和编辑的主干LLM。

    但是这个 LLM 在此时不进行训练。
    
    该LLM不是MLLM，因此需要 $Z_{uni}$ 伪装为可处理的文本，但其实则为处理后的声学特征。

    同时 $Z_{uni}$ 需要处理后才能被LLM处理。

    >   LLM?

        多模态 LLM 的通行做法——LLM 的输入层（Input Embedding Layer）本身是一个可训练的线性投影矩阵。对于文本 token，它查表得到向量；对于连续语音 token ，它通过一个可训练的线性层/MLP将其直接映射到 LLM 的隐藏维度（例如 4096 维），使其与文本 token 位于同一表征空间。


    把语义模块输出的 $Z_{uni}$ 输入给LLM，让LLM去预测这段音频对应的文本，计算交叉熵损失 $\mathcal{L}_{align}$，该损失通过LLM反向传播只更新语义模块的参数，迫使 $Z_{uni}$ 主动迎合这个LLM的语义空间。


#### Edit？

Audio-Omni、UNISON等的模型主体都是DiT，但是Ming-UniAudio的模型主体其实是一个主要的LLM、和对于三个任务的两个不同的头（文本头和自回归扩散头）。

编辑任务同时使用了文本头和扩散头。

利用了文本头，文本头输出CoT，LLM+文本头的中间东西叫隐藏状态，CoT不送给扩散头，但是隐藏状态送给扩散头。
