## 架构

文本编码器,BPE分词(CosyVoice部分) + $S^3$ 语音分词器 + LLM + GOT-CFM流匹配模型

LLM 是主干，负责从 源语音token 生成 目标语音token。

## 特点

主流使用 VAE ，而 CosyEdit 采取离散编码 

使用 LLM 对语音分词结果处理而不是 MLLM 直接处理语音

仅是针对文字内容的增删改的 Edit 模型

使用 CosyVoice 进行 Post-training

## 笔记

### 上下文预测？

范式：Edit -> 预测 edit 后整个目标语音

作为参照，VoiceBox 和 VoiceCraft 都是采用 Edit部分 拼接 未 Edit 部分。

>   VoiceBox - 传统级联系统。先用 MFA 算出哪一秒到哪一秒是待改区域。

### 无语义理解？

因为仅是针对文字内容的增删改，所以直接输入目标文本。

推理输入：

[起始符，说话人向量，目标文本编码，原始语音语义令牌，分隔符，目标语音令牌(待预测)，终止符]

### 互补的上下文学习范式？

在训练时，为了让模型仅靠“目标文本与原语音内容之间的差异”来推断编辑边界：

- 单次上下文学习（OICL）：[原始文本 + 目标文本 + 原始语音]
- 零次上下文学习（ZICL）：[目标文本 + 原始语音]

### GOT-CFM？

未来的主流是 DiT 执行了从源潜向量生成目标潜向量的任务，然后使用 VAE 的解码器还原音频。

而这里使用的是一个底层为流匹配的模型，根据 离散token 进行还原音频的梅尔谱。

后序还需要 HiFi-GAN 声码器还原音频。
