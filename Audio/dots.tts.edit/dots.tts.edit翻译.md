# dots.tts.edit: 基于连续自回归模型的精确控制语音编辑

dots.tts 团队

在线体验：huggingface.co/spaces/dots-studio/dots.tts.edit  
演示页面：huggingface.co/spaces/dots-studio/dots-tt-edit-demo

## 摘要

面向内容创作的语音编辑需要精确控制两个方面：编辑的内容和编辑的位置。自由形式的自然语言为表达编辑请求提供了灵活的接口，但其模糊性可能导致预期操作、参数或目标区域未充分指定。我们研究一种精确且显式的语音编辑接口：基于转录的、带有XML风格标签的结构化编辑指令，明确指定操作类型，并将其定位到转录跨度或边界。这种语义时间线避免了显式时间戳对齐，并为组合编辑提供了可外部检查的契约。我们在 dots.tts.edit 中实例化了该接口，这是一个从连续自回归 dots.tts 基础模型改编而来的编辑器。四个代表性的语音创作控制涵盖了词汇内容、情感表达、音高和语速传递，以及通过文本、情感、韵律和停顿编辑实现的时相 phrasing。任务特定的数据流程构建了操作和范围受控的配对数据，同时保留目标区域之外的源上下文。我们还引入了 doteBench，一个双语评估套件，用于测量四项控制及其组合的精确指令遵循、局部保持和音频质量。实验表明，在其五个编辑类别中，该模型在整体指令遵循和局部保持方面领先，而音频质量与现有的开源系统相当。在三个 Seed-TTS-Eval 分片上的零样本 TTS 识别错误率和说话人相似度与基础模型差异可忽略。代码和模型即将发布。

## 1 引言

面向内容创作的语音编辑不仅仅是生成合理的语音。编辑器必须让创作者能够说明哪个属性应该改变、朝哪个方向、改变多少，以及精确作用于现有录音的哪个部分。历史上，语音编辑对词汇纠正提供了最明确的控制：插入、删除或替换单词，同时匹配周围的声音和声学特征 (Jin et al., 2017; Tan et al., 2021; Wang et al., 2022; Bai et al., 2022)。实际创作还需要改变选定短语的情感表达、音高或语速，或者调整 phrasing 边界，而不干扰话语的其余部分。

最近的编辑基准（如 MMAE）使用自由形式的自然语言作为指定编辑请求的接口 (Ma et al., 2026)。这种表示是灵活的，但其灵活性也可能引入歧义：文本引用可能允许多种解释，而预期操作类别、参数或目标区域可能仍未充分指定。此外，专业创作经常需要可重复的控制，其请求的效果和范围可以独立检查。这种场景受益于编辑指令的精确且显式的表示。一种机器可读、可检查且可组合的表示也适合作为音频创作工作室或智能体音频创作工作流中的可调用后端。

图1：一个显式的编辑程序。带有 XML 风格标签的基于转录的结构化编辑指令指定了操作类别和参数，而彩色跨度和边界则定位其效果。转录渲染将 “meeting” 替换为 “concert”；情感和停顿操作改变了表达方式而不改变其余单词。目标渲染中的颜色和 \(\parallel\) 是标记编辑内容、表达方式和插入停顿的可视化注释；它们不是 \(T_{\mathrm{tgt}}\) 的一部分。

我们沿两个轴形式化这种精确性。**精确的操作规范**使得操作类别、方向和参数明确——编辑什么以及如何编辑。**精确定位**指明其应用位置。绝对时间戳需要显式的时间对齐意识，这对用户和许多音频理解系统都具挑战性，而声学边界通常模糊。因此，基于转录的语义时间线在大多数语音编辑场景中更实用且更易于交互。因此，我们提出一种基于转录的、带有 XML 风格标签的结构化编辑指令。自然语言描述仍然可以表达开放属性（如情感），而类型化标签使操作类别和参数明确，将每个操作的作用域绑定到语言跨度或词边界，并按源顺序序列化多个非重叠操作。该表示使得请求的行为可外部检查。图1说明了组合编辑中这两种精确性的形式。

语音创作请求的空间比任何固定任务列表都要广泛。我们选择了四个代表性的、反复出现的控制类型，它们涉及不同的操作类别和定位模式。**文本编辑**改变跨度或边界处的词汇内容。**情感编辑**全局地或在选定跨度上改变情感表达。**韵律编辑**在跨度上控制音高或语速。**停顿编辑**在词边界处改变时间结构。

实现这种形式仍然困难。输出必须执行每个请求的操作，保持非目标内容和声学特征，并且即使局部编辑改变时长也能保持连贯。自然录音很少提供仅在某个请求属性上不同的配对话语，而对齐、重合成和拼接可能引入附带变化。因此，评估必须将目标执行与局部保持和整体音频质量区分开来。

我们在 dots.tts.edit 中实例化了该形式，改编自连续的 dots.tts TTS 基础模型 (Lian et al., 2026)。模型以源语音和显式编辑程序为条件，其确定性转录渲染提供源和目标转录，然后在基础模型的连续潜在空间中生成目标语音。任务特定的流程在通用的音频-指令-音频契约下为四个代表性类别构建受控对。多个操作可以组合在一条指令中并在一次生成中执行。

我们还引入了 **doteBench**，一个双语评估套件，具有精确的、范围感知的指标。**指令遵循**测试请求的操作是否实现，**局部保持**测试其指定位置的补集，**音频质量**评估完整输出。在文本、情感、韵律、停顿和组合编辑上，dots.tts.edit 在所评估的开源音频生成和语音编辑系统中实现了领先的整体指令遵循和局部保持，同时保持相当的音频质量。其在 Seed-TTS-Eval 上的识别和说话人相似度得分仍然接近最强的 dots.tts 变体。

我们的贡献是：

- 一种精确的编辑表示，明确指定类型化操作和参数，并将其定位到转录跨度或边界，支持可检查的组合控制；
- 一个连续自回归语音编辑器及其任务特定数据流程，在相同的操作和范围受控配对数据接口下学习四个代表性创作控制；
- 以及 doteBench，一个双语套件，用于评估单个和组合编辑的精确指令遵循、局部保持和音频质量。

## 2 相关工作

**基于文本的语音编辑**。VoCo 结合合成、检索、语音转换和拼接，在现有旁白中替换语音 (Jin et al., 2017)。随后神经编辑器从文本和周围语音学习缺失区域的声学特征：EditSpeech 使用部分推理和双向融合 (Tan et al., 2021)，CampNet 预测掩码语音 (Wang et al., 2022)，\(\mathrm{A}^3\mathrm{T}\) 引入了对齐感知的声学-文本预训练 (Bai et al., 2022)。FluentEditor 变体正则化边界声学和全局韵律 (Liu et al., 2023, 2024)，而 UniCATS 使用语义 token 上的上下文 VQ-扩散 (Du et al., 2023)。基础规模系统通过 Voicebox 中的流匹配 (Le et al., 2023) 和 VoiceCraft 中的自回归编解码器生成 (Peng et al., 2024) 扩展填充；CosyEdit 和 AST 改编预训练 TTS 模型以进行精确内容编辑 (Chen et al., 2026; Lv et al., 2026)。许多此类系统依赖显式对齐器模块将编辑后的转录跨度映射到被掩码或重新生成的声学区域。这一进展改善了实现、边界流畅性和上下文连续性，但主要研究词汇编辑而非传递的局部控制。

**通用生成与属性编辑**。SpeechX 提示一个编解码器语言模型进行 TTS、增强、提取和编辑 (Wang et al., 2023a)。Step-Audio-EditX 执行情感、说话风格和副语言的话语级迭代编辑 (Yan et al., 2025a)，而 SpeechEdit 在 TTS 生成期间选择性控制说话人、情感和韵律属性 (Pei et al., 2026)。Ming-UniAudio 支持自由形式内容编辑和话语级声学变化 (Yan et al., 2025b)。UniSAE 将局部内容编辑从子音素扩展到词级，并与说话人和情感控制组合 (Zhu et al., 2026)。除语音属性外，MMEdit 定位通用音频事件，而 Audio-Omni 和 UNISON 统一了跨语音、声音、音乐或音频场景的编辑 (Tao et al., 2025; Tian et al., 2026; Li et al., 2026a)。因此，现有系统提供内容的局部控制或语音属性的话语级控制。据我们所知，dots.tts.edit 是第一个端到端编辑器，同时支持细粒度的局部文本、情感、韵律和停顿编辑，同时保持未请求区域和属性不变。

**语音编辑基准**。RealEdit 针对多样声学中的零样本内容编辑 (Peng et al., 2024)，LibriSpeech-Edit 增加了受控文本和风格编辑及时间一致性度量 (Lv et al., 2026)。SpeechEditBench 涵盖内容、情感、韵律和其他四种原子编辑任务，以及组合编辑 (Zhang et al., 2026)。其对非内容任务的保持-成功门仅检查 ASR WER/CER，因此不评估源韵律或其他副语言属性是否保持。MMAE 将覆盖范围扩展到多模态和混合声学场景，具有复杂指令和局部或全局操作 (Ma et al., 2026)。其细粒度指令遵循和一致性规则依赖于 Qwen3-Omni 判断 (Xu et al., 2025)。三次独立查询、多数投票和选项洗牌减轻了离散规则决策中的变异性和位置偏差，但所得分数仍受判断者细粒度感知能力的限制，且可解释性有限。doteBench 则定义了针对文本、情感、韵律、停顿和组合编辑的类别特定、范围感知协议，在指令遵循、局部保持和音频质量的共同评估下进行。MMAE 强调广度和自由形式任务，而 doteBench 强调对精确定位的语音控制的可解释执行和保持测量。

## 3 问题定义与基准

### 3.1 精确控制的语音编辑

我们将一个编辑样本定义为五元组

\[d_{\mathrm{edit}} = \left(T_{\mathrm{src}},A_{\mathrm{src}},u,T_{\mathrm{tgt}},A_{\mathrm{tgt}}\right),\qquad T_{\mathrm{src}} = g_{\mathrm{src}}(u),\quad T_{\mathrm{tgt}} = g_{\mathrm{tgt}}(u)。 \quad (1)\]

这里 \(T_{\mathrm{src}}\) 和 \(T_{\mathrm{tgt}}\) 分别是源和目标转录，\(A_{\mathrm{src}}\) 和 \(A_{\mathrm{tgt}}\) 是对应的波形，而 \(u\) 是一个带有 XML 风格标签的基于转录的结构化编辑指令。确定性渲染器 \(g_{\mathrm{src}}(u)\) 移除标签而保留源侧词汇内容，而 \(g_{\mathrm{tgt}}(u)\) 应用词汇插入、删除和替换。属性标签不改变转录。编辑器生成

\[\hat{A}_{\mathrm{tgt}} = f_{\theta}(T_{\mathrm{src}},A_{\mathrm{src}},u,T_{\mathrm{tgt}})。 \quad (2)\]

这里 \(f_{\theta}\) 是具有可训练参数 \(\theta\) 的编辑器，\(\hat{A}_{\mathrm{tgt}}\) 是其预测的目标波形。每个标签提供一个操作类别、其参数和一个定位。跨度操作包裹转录 token，而点操作标记词边界。这分离了精确操作规范与精确定位，并避免了让生成模型从未充分指定的请求中推断任一字段。成功的输出必须 (i) 实现每个带标签的操作，(ii) 保持标签位置之外的内容和属性，以及 (iii) 作为一个完整话语保持自然和连贯。

四个评估类别是代表性控制而非详尽的语音编辑分类。**文本操作**通过跨度或边界上的插入、删除或替换修改词汇内容。**情感操作**全局或在跨度上修改情感表达。**韵律操作**在跨度上改变音高或语速。**停顿操作**在边界处插入、延长或缩短时间结构。一个组合指令包含多个非重叠操作，并且仅当所有组件都实现时才算成功。

**可扩展性**。在语音内部，类型化词汇可以纳入额外的属性和编辑动作。其显式模式还提供了一个稳定的工具边界，工作室前端、规划器或智能体可以通过它构建、验证和调用编辑程序。更广泛地，结构程序原则可以扩展到非言语事件、通用音频或音乐，给定合适的符号时间线和配对监督；本工作仅评估语音。

### 3.2 doteBench

我们提出 doteBench，一个用于精确控制语音编辑的双语评估套件。它包含五个类别：文本编辑、情感编辑、韵律编辑、停顿编辑和组合编辑。前四个一次评估一个编辑家族，在单说话人话语上进行，具有显式的目标和保持区域。文本编辑有 Easy 和 Hard 两个划分；每个其他单任务类别有一个主要集合。组合编辑类别涵盖二操作、三操作和四操作指令；其指令遵循指标报告组件级别和全组件成功。三个评估维度与控制契约相匹配：**指令遵循**测试指定操作的执行，**局部保持**测试其定位之外的语音，**音频质量**测试完整结果。层次结构和案例数量如图2所示，表1总结了测量维度。

## 4 精确控制语音编辑的数据流程

### 4.1 构建挑战与共享原则

**挑战**。自然录音很少提供仅在某个局部属性上不同的同一话语的两个版本。一个有用的训练对必须展示请求的变化，同时保持内容、说话人身份和周围声学一致。这很难通过独立合成两侧来实现：时序、音色和渲染质量的差异可能被误认为预期的编辑。时长变化操作使难度增加，因为相同的语言跨度在源和目标时间线上占据不同位置。

**原则**。每个任务特定流程围绕一个具有明确操作类别、参数和定位的干预构建一个可溯源感知的原始/生成对，然后通过公式(1)中的通用编辑样本将其序列化。各流程在实现控制的方式上有所不同，但每个接受的对都暴露相同的操作和范围受控监督，而不是不相关的任务特定目标。受 ISSE (Chen et al., 2025) 中使用记录锚点和合成对应物的启发，我们将每个构建的对双向序列化。除了从一个干预获得双倍监督外，生成到原始方向将原始音频放在目标侧。当原始是录音时，这防止了目标监督完全依赖合成音频。

局部组装带来了第二个问题。直接将合成或信号处理的片段连接到周围上下文常常会产生可听见的接缝，而强制对齐器并不总是将连接点精确放在声学边界上。对于需要此类连接的流程，我们因此使用 F5-TTS (Chen et al., 2024) 的掩码重建能力，从其转录和声学上下文重新合成边界附近的一个短邻域。这种修复可能修改少量名义上未编辑的语音；我们接受这种对精确保持的受控放松，作为自然过渡和准确内容所必需的权衡。然后评估器检查指令有效性、编辑实现、可懂度、保持、说话人一致性和质量，然后保存器连同其对齐、干预参数、验证结果和源出处一起保留该对。

### 4.2 任务特定编辑流程

**文本编辑**。词汇更改同时改变口语内容和其时间线。对于插入、删除和替换，强制对齐首先将指令的源跨度映射到波形区间。然后我们构建一个目标时间线条件，其未编辑区间复制原始录音样本，其编辑区间被掩码。F5-TTS 从目标转录填充这些掩码，同时以两侧保留的语音为条件。因此，模型看到的是局部重新生成的词汇变化，而不是独立合成的目标话语，而反向指令将插入变为删除，删除变为插入，替换变为其逆操作。

**情感编辑**。情感编辑必须改变几个相关的声学线索，而不将说话人或内容变化转化为监督。我们从开源数据集中构建一个说话人平衡的中性音色池，包含 4,000 个说话人和约 1 百万个话语，并在 IndexTTS2 (Zhou et al., 2025) 中以相同文本但不同情感条件渲染时固定一个说话人提示。对于局部编辑，完整的目标情感实现保留为目标音频。为构建其配对的源，我们使用相同的实现作为声学基础，并将相应跨度从源情感实现拼接回去。因此，目标保持为一个连贯的、未拼接的 TTS 输出，两侧在捐助者和修复区域之外共享相同的波形。F5-TTS 在每个连接点周围重新生成一个窄邻域以抑制对齐和拼接伪影。交换两个情感实现并重复此构建，以相同的干净目标属性提供反向编辑。

**韵律编辑**。信号级韵律控制是精确的，但其本身可能扭曲语音并改变感知的说话人音色。PSOLA (Moulines and Charpentier, 1990) 应用请求的音高变化，WSOLA (Verhelst and Roelands, 1993) 应用请求的时间拉伸。然后我们使用 IndexTTS2 分词器和解码器重新合成变换后的片段。变换后的片段提供语义 token、说话人条件和风格特征，而原始片段提供基础说话人提示和梅尔参考。这种安排保留了预期的韵律变化，同时从原始录音恢复身份和自然度。语速编辑类似地在 WSOLA 后应用 IndexTTS2，以原始话语作为说话人参考。我们将两种类型的变换片段交叉淡入源；对于音高编辑，我们还应用窄 F5-TTS 边界修复。话语的其余部分从原始复制。

**停顿编辑**。停顿编辑需要显式的时长控制，但仅插入静音会创建不自然的进入和退出过渡。强制对齐定位指令的 linguistic 边界，在此我们根据请求的级别精确插入 200、500 或 800ms 的零值样本。F5-TTS 然后重新生成一个覆盖停顿和两侧语音上下文的短窗口，允许两个过渡适应新的时序。该修复窗口外的样本保持不变。原始到生成的记录教导停顿插入，而交换两个波形并反转指令则提供相应的停顿减少。

## 5 dots.tts.edit：连续自回归语音编辑

### 5.1 连续自回归主干

dots.tts 是一个 2B 参数的连续自回归 TTS 基础模型 (Lian et al., 2026)。它使用基于 HoliTok (Li et al., 2026b) 的 AudioVAE 表示 \(48\mathrm{kHz}\) 语音，产生 \(25\mathrm{Hz}\) 的潜在流。它将每四个帧的补丁减少为 \(6.25\mathrm{Hz}\) 的语义表示，并自回归预测表示，从中一个流匹配头渲染连续的潜在补丁。一个冻结的 CAM++ 说话人编码器 (Wang et al., 2023b) 提供全局身份条件。

---

### 5.2 编辑和 TTS 训练

训练混合普通 TTS 示例与第4节的配对编辑示例。令 \(Z_{\mathrm{src}} = \mathcal{E}_{\mathrm{VAE}}(A_{\mathrm{src}})\) 和 \(Z_{\mathrm{tgt}} = \mathcal{E}_{\mathrm{VAE}}(A_{\mathrm{tgt}})\) 表示由冻结编码器 \(\mathcal{E}_{\mathrm{VAE}}\) 产生的源和目标 AudioVAE 潜在序列，并令 \(\mathbf{e}_{\mathrm{spk}}\) 表示冻结的 CAM++ 说话人嵌入。编辑示例遵循序列 \([T_{\mathrm{src}},Z_{\mathrm{src}},u,T_{\mathrm{tgt}},Z_{\mathrm{tgt}}]\)。目标音频位置承载流匹配和停止监督，而 \(Z_{\mathrm{src}}\) 提供完整源话语作为声学上下文。TTS 和编辑保留不同的条件上下文，但共享相同的目标潜在生成器：

\[\underbrace{p_{\theta}(Z\mid T,\mathbf{e}_{\mathrm{spk}})}_{\mathrm{TTS}}\qquad \mathrm{和}\qquad \underbrace{p_{\theta}(Z_{\mathrm{tgt}}\mid T_{\mathrm{src}},Z_{\mathrm{src}},u,T_{\mathrm{tgt}},\mathbf{e}_{\mathrm{spk}})}_{\mathrm{编辑}}。 \quad (3)\]

这里 \(T\) 表示通用转录，\(Z\) 目标 AudioVAE 潜在序列，\(p_{\theta}\) 共享的条件生成器。因此 TTS 以请求的转录和说话人身份为条件，而编辑额外观察源转录、源语音、指令和目标转录。所有编辑家族使用第二种分解而不是独立的任务头。

对于每个监督的目标补丁 \(x_{1}\)，流匹配 (Lipman et al., 2023) 抽取标准高斯噪声 \(x_{0} \sim \mathcal{N}(0, I)\)（\(I\) 是单位协方差）和时间 \(t \sim \mathcal{U}(0, 1)\)。在配置的零终端噪声尺度下，它形成 \(x_{t} = t x_{1} + (1 - t) x_{0}\) 并使用目标速度 \(v^{\star} = x_{1} - x_{0}\)。自回归主干为该补丁级速度场提供因果语义历史和条件上下文。训练目标为

\[\mathcal{L} = \lambda_{\mathrm{FM}}\mathbb{E}\Big[\| v_{\theta}(x_{t},t;c) - v^{\star}\|_{2}^{2}\Big] + \lambda_{\mathrm{CE}}\mathcal{L}_{\mathrm{CE}} + \lambda_{\mathrm{EOS}}\mathcal{L}_{\mathrm{EOS}}, \quad (4)\]

其中 \(v_{\theta}\) 是预测速度，\(c\) 是公式(3)中对应的 TTS 或编辑上下文。期望遍历训练示例、目标补丁、高斯噪声和插值时间。\(\mathcal{L}_{\mathrm{CE}}\) 是掩码的下一个 token 交叉熵，\(\mathcal{L}_{\mathrm{EOS}}\) 预测每个音频跨度的结束；损失权重 \(\lambda_{\mathrm{FM}}\)、\(\lambda_{\mathrm{CE}}\) 和 \(\lambda_{\mathrm{EOS}}\) 均为 1。损失在组合前按其活跃的 token 或潜在补丁掩码进行归一化。

## 6 实验

我们的实验提出四个问题：编辑器是否执行明确指定的操作，是否保持其定位之外的语音，多个操作能否在一次生成中组合，以及编辑后训练是否保留基础模型的零样本 TTS 能力。doteBench 通过指令遵循、局部保持和音频质量与现有开源音频生成和语音编辑模型及任务特定流程的比较来回答前三个问题。Seed-TTS-Eval 提供补充的 TTS 保持测试。

### 6.1 设置

#### 6.1.1 训练

**模型初始化**。dots.tts.edit 从公开的 2B 参数 dots.tts 检查点 (Lian et al., 2026) 初始化所有编辑器参数，其权重可在线获取。主干包括一个 Qwen2.5-1.5B 语言模型 (Qwen Team, 2024)、一个 24 层语义编码器和一个 18 层自回归流匹配 DiT (Peebles and Xie, 2023)，在冻结的 48 kHz AudioVAE 的四帧补丁上操作。一个冻结的 512 维 CAM++ 说话人编码器 (Wang et al., 2023b) 提供语音条件；我们使用 VoxCeleb 训练的公开检查点。

**目标与优化**。我们端到端优化流匹配、音频停止和语言模型目标，同时保持 AudioVAE 和说话人编码器固定。训练使用 bfloat16 算术、AdamW (Loshchilov and Hutter, 2019) 学习率 \(2\times 10^{- 5}\)、动量系数 \(\beta_{1} = 0.9\) 和 \(\beta_{2} = 0.99\)、权重衰减 0.01、梯度累积 2 和梯度裁剪为 2。WSD 调度 (Hu et al., 2024) 使用 1,000 步线性预热和 15,000 步线性衰减至峰值率的 \(15\%\)。

**训练混合**。TTS 回放从基础模型使用的 150 万小时多语言语料 (Lian et al., 2026) 中采样。在训练加载器的在线质量过滤器之前，编辑清单包含约 11M 文本、10M 情感、8M 韵律和 5M 停顿对。TTS:文本:情感:韵律:停顿的近似采样权重为 48:4:4:2:1；因此混合物保留了原始合成通路，同时重复暴露模型于局部编辑。

**增强**。对于 \(60\%\) 的编辑示例，我们拼接两到三个独立采样的片段，总长最多 40 秒，创建更长的、组合的、可能多说话人的上下文，以训练每个说话人身份的保持。所有拼接示例丢弃全局 CAM++ 说话人嵌入。10-20 dB SNR 的噪声增强支持语音增强和背景噪声保持。TTS 回放不进行增强。

#### 6.1.2 评估

**基线**。开源模型比较包括 Step-Audio-EditX (Yan et al., 2025a)、Ming-UniAudio (Yan et al., 2025b)、Qwen3-Omni (Xu et al., 2025)、MiMo-Audio-Instruct 和 MiMo-Audio-Base (Xiaomi LLM-Core Team, 2025)，以及 Kimi-Audio (Kimi Team, 2025)。对于每个基线，我们尽可能将编辑指令适配到其公共接口支持的指令格式和条件示例。表格中还报告了复制源音频而不执行指令的 Identity 参考。对于 Seed-TTS-Eval，我们报告 dots.tts.edit 的结果，并引用 dots.tts 技术报告 (Lian et al., 2026) 中的所有基线值。比较的系统是三个 dots.tts 变体、Seed-TTS (Seed Team, ByteDance, 2024)、Qwen3-TTS (Hu et al., 2026) 和 VoxCPM2 (Zhou et al., 2026)。

**基准**。主要评估包括五个 doteBench 类别。对于文本编辑，主要比较使用 Hard 划分；Easy 划分包含在表2中供参考，不合并到头条分数。所有 doteBench 系统在相同的冻结清单上进行评估。生成失败保留在指标分母中并带有固定惩罚，而 WDTW 项仅在清单未定义符合条件的保持区域时省略。由此产生的跳过集独立于候选系统。Seed-TTS-Eval 在官方 WER/CER 和说话人相似度协议下使用 1,088 个英语、2,020 个中文和 400 个中文 Hard 示例。

**推理参数**。推理时，dots.tts.edit 使用欧拉积分，10 个流步，无分类器引导尺度 1.2 (Ho and Salimans, 2022)，说话人引导 1.5，bfloat16 推理，最大生成长度 500 个潜在步。

**组合编辑**。在组合编辑类别上，dots.tts.edit 将组件成功率相对 MiMo-Audio-Instruct（组件成功率 30.62%）提高了 98.82%，全组件成功率相对 Qwen3-Omni 和 MiMo-Audio-Instruct 并列的 7.08% 提高了 323.53%。它在表6的每个家族特定成功率以及除 UTMOS 外的每个保持指标上都领先所有评估的开源模型。其 \(60.87\%\) 的组件成功率和 \(30.00\%\) 的全组件成功率对应于文本/情感/韵律/停顿组件率分别为 \(86.23 / 18.84 / 79.71 / 58.70\%\)。文本仍然是最强的组件，情感最弱，而韵律和停顿在多操作编辑中也有很大的改进空间。顺序组合任务特定流程得到 \(67.57\%\) 的组件成功率和 \(34.17\%\) 的全组件成功率。流程基线获得文本/情感/韵律/停顿组件成功率分别为 \(85.51 / 23.19 / 98.55 / 63.04\%\)。

我们进一步将编辑器与数据构建流程进行比较。在文本编辑上，基础模型主干比“对齐-然后-编辑”流程更稳健地处理困难的目标转录。对于声学编辑，专家流程通过隔离每个编辑区域、局部应用请求操作并保留剩余波形，建立了强的指令遵循和保持上限。dots.tts.edit 在所有这些轴上并未达到每个流程上限，但在所有五个类别上使用一个模型和一次生成获得了更高的 UTMOS；组合流程基线需要顺序调用多个任务特定流程。这种单模型、单次生成设计简化了部署。

## 7 结论

我们提出了 dots.tts.edit，一个基于连续自回归 TTS 模型的精确控制语音编辑器。其基于转录的、带有 XML 风格标签的结构化编辑指令使操作类别和参数明确，并将其定位到转录跨度或边界。文本、情感、韵律和停顿编辑实例化了四个代表性的创作控制，而任务特定流程构建了操作和范围受控的对。然后 doteBench 类别评估请求操作是否执行、非目标语音是否保持以及完整结果是否自然。

在五个 doteBench 类别中，dots.tts.edit 在所评估的开源系统中展示了领先的整体指令遵循和局部保持，同时保持相当的音频质量。Seed-TTS-Eval 进一步显示编辑后训练在很大程度上保持了基础模型的合成能力：在三个分片上，识别误差与最强 dots.tts 变体的绝对差异最多 \(0.29\%\)，说话人相似度最多 0.011。这些结果支持结构指令作为人类引导工作室界面和智能体中介编辑工作流中单个和组合语音编辑的实用、可检查接口。

---

## 限制

当前模型可以保持话语中多个说话人的身份，但不支持说话人转换；doteBench 也尚未涵盖多说话人编辑任务。当前实验也未提供自然语言接口与结构接口之间的匹配比较。因此，我们的精确性声明关乎控制契约的明确性和可检查性，而非确定性生成或对自然语言编辑的因果优越性。我们尚未在端到端智能体集成中评估 dots.tts.edit。此外，尽管 dots.tts.edit 在评估类别上达到了比数据构建流程基线更高的预测感知质量，其音频质量仍有很大的提升空间。更先进的非自回归基础 TTS 或描述到语音模型可能使数据构建流程具有更少的合成和平滑阶段以及更流畅的音频；我们将此方向留待未来工作。
